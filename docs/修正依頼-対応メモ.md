# 修正依頼 対応メモ

## 実施した対応

### バグ修正
- **家族一覧での画像の修正（再登録）ができない**: 編集開始時にファイル入力用の key を更新するようにし、毎回新しいファイル入力が表示されるようにしました。これにより、同じ子の編集で別の画像を選び直しても正しく送信されます。

### 改善修正
- **テーマカラー追加**: オレンジ・えんじ・水色・ミント・紫・赤を追加しました（かぞく一覧の色選択肢と、円盤・表示用の colors.ts の両方）。
- **当選履歴の1件削除**: 各履歴に「削除」ボタンを追加。削除するとその当選結果だけが消え、当選した子の `is_selected` が false に戻り、ルーレットに復活します。
  - API: `DELETE /api/histories/:id`
  - バックエンド: 履歴削除と該当 doll の is_selected を false に更新するトランザクションを実装。

### 仕様追加修正
- **お出かけ日記**:
  - ナビに「お出かけ日記」を追加。
  - 登録項目: 場所・**日付のみ**（時間なし）・どの家族と（複数可）・**写真は複数枚可**・コメント。
  - 一覧で概要表示、**行タップで詳細を手前にオーバーレイ表示**（家族一覧と同様）。詳細で「一緒に」を写真の上に表示（名前はテーマカラー）、複数画像をグリッド表示。
  - **編集**: 場所・日付・一緒に・コメントの更新。写真の**追加**（POST `/api/outings/:id/images`）・**削除**（POST `/api/outings/:id/images/remove`）。**写真削除時は「この画像を削除しますか？」で確認**。
  - **削除**: 日記ごと削除（DELETE `/api/outings/:id`、確認あり）。
  - **画像全体表示**: 詳細画面で写真をタップするとモーダルで画像全体を表示。
  - DB: `db/init/01_schema.sql` に `outings` / `outing_dolls` / `outing_images` を追加。既存環境用に `02_outings.sql`、`03_outing_images.sql` あり。

- **家族の複数画像**:
  - **doll_images** テーブルを追加（01_schema に含む。既存DBは `04_doll_images.sql` を1回実行）。
  - **一覧**: 行タップで詳細オーバーレイを表示。一覧のサムネイルは**代表画像（doll.image_url）優先**（なければ image_urls[0]）。サブ画像の追加・削除では一覧の画像は変わらない。
  - **詳細**: 名前・色・代表画像（1枚）・サブ画像（複数）を表示。ここから編集・削除。
  - **編集**: 詳細内で代表画像の差し替え（1枚）・削除、サブ画像の追加（複数）・削除。追加は POST `/api/dolls/:id/images`、削除は POST `/api/dolls/:id/images/remove`（JSON body）。画像更新後はキャッシュバスターで再表示。

- **ルーレットの当選画像**:
  - **代表画像（dolls.image_url）・サブ画像（doll_images）を合わせた中からランダムで1枚**を結果表示。
  - **履歴にはその時に出た画像を保存**（`histories.doll_image_url`）。既存DBは `05_histories_image_url.sql` を1回実行。

- **画像まわりその他**:
  - ファイルサイズ制限は廃止（家庭内運用のため）。枚数はお出かけ・家族とも上限 100 枚程度。
  - 画像削除は DELETE ではなく POST `.../images/remove` + JSON body で確実に届くように変更。
  - 一覧で画像を更新したあと、ページを更新しなくても一覧の画像が変わるよう、refetch 時にキャッシュバスター（`?v=...`）を付与。

- **スマホ接続**:
  - API 向き先を「同じホスト:3000」で自動判定するように変更。`VITE_API_BASE_URL` 未設定かつ localhost 以外から開いた場合、そのホストの 3000 番を使うため、日をまたいで IP が変わっても、その日に開いたアドレスで API に届く。

## 既存DBで必要な実行（まとめ）

- お出かけ日記をまだ入れていない場合:
  ```bash
  cat db/init/02_outings.sql | docker compose exec -T db psql -U doll_roulette -d doll_roulette
  cat db/init/03_outing_images.sql | docker compose exec -T db psql -U doll_roulette -d doll_roulette
  ```
- 家族の複数画像を使う場合（01_schema に含まれていない既存DBのみ）:
  ```bash
  cat db/init/04_doll_images.sql | docker compose exec -T db psql -U doll_roulette -d doll_roulette
  ```
- 当選時に表示した画像を履歴に残す場合:
  ```bash
  cat db/init/05_histories_image_url.sql | docker compose exec -T db psql -U doll_roulette -d doll_roulette
  ```

## 仕様修正の相談（複数枚写真）への回答

**質問**: 家族の写真を複数枚登録したい。現状のDBデータを残したいが、DB構成を変えなければならないか。実現可能か。

**回答**: **実現可能です。** 現状のデータを残したまま、DB構成の拡張で対応しました。

### 実施した方針
- **dolls テーブルはそのまま**にし、`image_url` も残しています（代表画像・1枚のみの場合はここを使用）。
- **doll_images** テーブルで「1体 : 複数画像」を表現。`db/init/01_schema.sql` に含め、既存DB用に `04_doll_images.sql` も用意。
- フロントでは編集時に「現在の写真」一覧・削除・代表画像の差し替え・写真を追加（複数）を提供。
- ルーレット当選時は代表画像・サブ画像を合わせた中からランダム1枚を表示し、そのURLを `histories.doll_image_url` に保存して履歴でも同じ画像を表示。
