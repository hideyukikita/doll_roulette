# かぞくたちルーレット 基本設計書

**完成版**。システムの目的・スコープ・機能概要・非機能要件を定義します。

---

## 1. プロジェクト概要

### 1.1 目的

飼っているぬいぐるみ（かぞく）を**平等に**選び、一緒に寝る子を**楽しく**決めるためのアプリを提供する。

### 1.2 スコープ

- **対象ユーザ**: 家庭内でぬいぐるみを複数持っている人（主に自分または家族）
- **利用環境**: 同一 Wi-Fi 内の PC またはスマートフォン（WSL2 + Docker 上で動作）
- **対象外**: 不特定多数向け公開、認証・複数アカウント、クラウド本番運用（将来拡張で検討可）

### 1.3 用語

| 用語 | 説明 |
|------|------|
| かぞく | 登録したぬいぐるみ1体。名前・色・画像で管理する。 |
| 代表画像 | かぞくに1枚だけ設定するメイン画像。一覧のサムネイルにも使用。 |
| サブ画像 | かぞくに追加できる複数画像。ルーレット当選時に代表 or サブからランダム1枚を表示。 |
| 当選 | ルーレットで選ばれたこと。1回当選すると「選択済み」となり、次回はほぼ選ばれにくくなる。 |
| リセット | 全員の選択状態と当選履歴をクリアし、再度ルーレットで全員が選ばれるようにする操作。 |
| お出かけ日記 | 場所・日付・一緒に行ったかぞく・写真・コメントを記録する機能。 |

## 2. システム構成

### 2.1 アーキテクチャ

- **フロントエンド**: SPA（React + Vite + Tailwind CSS）。画面: かぞく一覧・お出かけ日記・ルーレット。
- **バックエンド**: REST API（Node.js + Express）。CRUD・画像アップロード・ルーレット抽選・リセット。
- **データベース**: PostgreSQL（dolls, doll_images, histories, outings, outing_dolls, outing_images）。
- **インフラ**: Docker Compose で db / backend / frontend の3コンテナ。画像は /uploads をボリュームで永続化。

### 2.2 外部インターフェース

- **ユーザ**: ブラウザ（PC またはスマホ）でフロントにアクセス。
- **フロント → バックエンド**: REST API（JSON）。画像は multipart/form-data。API ベース URL は環境変数または同一ホストで自動判定。
- **バックエンド → DB**: PostgreSQL プロトコル（コンテナ間）。

## 3. 機能概要

### 3.1 かぞく管理

登録・一覧・詳細（オーバーレイ）・編集・削除。代表画像・サブ画像。画像タップで全体表示。**画像全体表示画面でダウンロードボタンから端末に保存可能**。

### 3.2 お出かけ日記

登録・一覧・詳細（オーバーレイ）・編集・削除。写真複数・写真タップで全体表示。写真削除時は確認あり。

### 3.3 ルーレット

円盤で未選択から1体当選。当選画像は代表 or サブからランダム1枚を履歴に保存。全員一周でリセットまで停止。当選履歴は行タップで詳細・画像タップで全体表示。

### 3.4 リセット

全員の選択状態と当選履歴をクリア。確認ダイアログあり。

## 4. 非機能要件

- **性能**: 家庭内利用想定。同時利用者はごく少数。
- **運用**: ローカル Docker。バックアップは利用者がボリュームを取得する想定。
- **セキュリティ**: 認証なし。同一ネットワーク前提。本番公開時は認証・HTTPS 等の追加が必要。
- **保守性**: 設計・API・DB は docs/ に記載。

---

## 5. 制約・前提

- WSL2 (Ubuntu) / Windows 上で Docker Compose が動作すること。
- スマホ利用時、WSL2 の場合は Windows でポート転送（例: scripts/Connect-WSL.ps1）が必要。
- フロントの API 向き先は、localhost 以外から開いた場合は「同じホスト:3000」を自動使用（環境変数で上書き可）。
