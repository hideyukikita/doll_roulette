# リファクタリング設計書（一から作る場合の設計）

**目的**: 同様の機能を一から実装する前提で、DB・ディレクトリ・ストレージ・Docker を整理した設計。

---

## 1. DB 設計（クリーンスキーマ）

### 方針

- **画像はすべて *_images テーブルに集約**。`dolls.image_url` / `outings.image_url` は廃止（レガシー）。
- **代表画像** = 各 `*_images` の `sort_order` が最小の 1 件。同一なら `created_at` 昇順の先頭。

### テーブル

| テーブル | 説明 | 主なカラム |
|----------|------|------------|
| **dolls** | かぞく | id, name, color, is_selected, created_at |
| **doll_images** | かぞくの画像（複数可） | id, doll_id, image_url, sort_order, created_at |
| **histories** | 当選履歴 | id, doll_id, doll_image_url（当選時に表示した画像）, selected_at |
| **outings** | お出かけ日記 | id, place, outing_date, comment, created_at |
| **outing_dolls** | お出かけ×かぞく 多対多 | outing_id, doll_id |
| **outing_images** | お出かけの写真 | id, outing_id, image_url, sort_order, created_at |

- 既存データはマイグレーションで `doll_images` / `outing_images` に移行し、その後カラム削除。

---

## 2. ディレクトリ構成（バックエンド）

```
backend/
  src/
    config/         # 設定の集約（DB・ストレージ・アプリ）
      db.ts
      storage.ts
      index.ts
    storage/        # 画像保存の抽象層
      types.ts      # IStorage インターフェース
      local.ts      # ローカルディスク実装
      index.ts
    db/             # DB 接続
      client.ts
    routes/         # HTTP ルート（薄く、サービス＋ストレージを呼ぶだけ）
    services/       # ビジネスロジック・DB アクセス
    types/           # 型定義
```

- **routes**: multer で受信し、ストレージ層に保存パスを渡す。保存先の詳細は知らない。
- **storage**: `save(buffer, path)` / `delete(path)` / `getPublicUrl(path)`。実装はローカル（将来 OCI 等を追加可能）。

---

## 3. 画像パス規則

- **かぞく**: `dolls/{dollId}/{uuid}.{ext}`
- **お出かけ**: `outings/{outingId}/{uuid}.{ext}`
- DB には **パス**（例: `/uploads/dolls/xxx/yyy.jpg`）を保存。公開 URL は config のベース URL と組み合わせて生成。

---

## 4. Docker

- 現状の 3 コンテナ（db / backend / frontend）を維持。
- 環境変数で DB・ストレージ種別を注入。`.env` はリポジトリに含めない。

---

## 5. API レスポンス（互換）

- フロントは **変更なし**で動くようにする。`doll.image_url` は `image_urls[0] ?? null` で返す。`image_urls` は `doll_images` の並び順どおり。
