# 本移設 作業手順（表示用）

**目標**: 現在のデータをそのまま移行し、Oracle Cloud 上でベストな構成（リファクタ済み＋セキュリティ）で動かす。  
**前提**: **無料（Always Free）で行う**ことが第一。ドメインは必須ではありません。

---

## ドメインについて

| 質問 | 回答 |
|------|------|
| **ドメインの取得はいる？** | **必須ではありません。** パブリック IP だけでアクセスできます（例: `http://123.45.67.89`）。 |
| **ドメインがあると何がいい？** | **HTTPS（Let's Encrypt）** を無料で使う場合、証明書の発行にドメインが必要です。ドメインがなくても **HTTP のまま** 運用すれば、パスワード認証で十分使えます。 |
| **無料ドメインは？** | 使いたい場合は、無料のダイナミック DNS（No-IP など）や、有料の安いドメイン（数百円/年）を後から取得して HTTPS 化する選択肢があります。**まずは IP のみで移設して問題ありません。** |

## E2.1.Micro しか Always Free にない場合

**状況**: 作成画面で **VM.Standard.A1.Flex（Ampere）が選べず、VM.Standard.E2.1.Micro だけ**が Always Free 対象になっていることがあります（リージョンやキャパの都合）。

**E2.1.Micro の仕様**: 1 OCPU・**1 GB メモリ**。このアプリ（PostgreSQL + Node + Nginx）を 1 台で動かすには**メモリがかなり厳しい**ですが、以下の工夫で**動かせないことはありません**。

### やること（E2.1.Micro で進める場合）

1. **スワップを追加する**（必須に近い）  
   SSH で VM に入り、例として 2 GB のスワップを追加します。
   ```bash
   sudo fallocate -l 2G /swapfile
   sudo chmod 600 /swapfile
   sudo mkswap /swapfile
   sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   ```

2. **フロントは「本番ビルドのみ」にする**  
   VM 上では **Vite の開発サーバーは使わず**、手元の PC で `npm run build` した `frontend/dist` を rsync で VM に転送し、Nginx で配信する形にします。手順 5 の「VM 上で Node を入れてビルド」は E2.1.Micro だとメモリを圧迫するため、**手元でビルドして転送**を推奨します。

3. **Docker は db と backend だけ**  
   VM 上では `docker compose up -d db backend` のみとし、frontend コンテナは起動しません。静的ファイルは Nginx が `frontend/dist` を直接参照します。

4. **余裕があれば**  
   PostgreSQL の `shared_buffers` を小さくする（例: 128MB）、Ubuntu の不要なサービスを止める、などでメモリを少しでも減らせます。

### A1（Ampere）をあとから試す場合

- **A1 は「out of host capacity」** で出ないことがあります。**時間や曜日を変えて再試行**したり、**別リージョン（例: 大阪）** でインスタンス作成を試すと、A1 が選べる場合があります。
- E2.1.Micro で一旦移設し、後日 A1 が取れたらインスタンスを作り直し、データだけ移す運用も可能です。

**まとめ**: **E2.1.Micro だけでも問題なく移設は進められます。** スワップ追加と「フロントは手元ビルド＋Nginx 配信」「コンテナは db と backend のみ」を守れば、1 GB でも動作を狙えます。

## 全体の流れ（番号順）

| # | 段階 | どこで | やること |
|---|------|--------|----------|
| 1 | **ローカル準備** | 手元の PC | pre を止め、ルートで DB をリファクタ後スキーマに移行 → ダンプ・画像退避 |
| 2 | **Oracle 準備** | Oracle コンソール | VM 作成（Always Free）・セキュリティリスト・SSH 確認 |
| 3 | **VM セットアップ** | Oracle VM（SSH） | Docker 導入・リポジトリ clone／rsync・本番 .env |
| 4 | **データ投入** | Oracle VM | DB リストア・画像を backend の uploads に配置 |
| 5 | **アプリ・Nginx** | Oracle VM | フロントビルド・全コンテナ起動・Nginx で 80 番をプロキシ |
| 6 | **公開後** | Oracle VM | アイドル対策（cron）・動作確認 |
| (任意) | **ベスト構成の追加** | Oracle VM | Object Storage・Block Volume・HTTPS（ドメインありの場合） |

**すべて Always Free の範囲で実施できます。** 任意の Object Storage・Block Volume も無料枠内です。

---

## 手順 1: ローカル準備（手元の PC）

**目的**: 移設用の「リファクタ後スキーマのダンプ」と「画像フォルダ」を用意する。

1. **pre を止める**
   ```bash
   cd pre
   docker compose -p doll_roulette down
   cd ..
   ```

2. **ルートで DB だけ起動**
   ```bash
   cd doll_rouletteのルート
   docker compose up -d db
   ```
   数十秒待つ。

3. **バックアップを取る（必須）**
   ```bash
   docker compose exec db pg_dump -U doll_roulette doll_roulette > backup_before.sql
   ```

4. **リファクタ後スキーマへマイグレーション**
   ```bash
   cat db/migrations/001_drop_legacy_image_urls.sql | docker compose exec -T db psql -U doll_roulette doll_roulette -f -
   ```

5. **Oracle 用ダンプを取得**
   ```bash
   docker compose exec db pg_dump -U doll_roulette doll_roulette > backup_for_oracle.sql
   ```

6. **画像を退避**
   ```bash
   docker compose up -d backend
   mkdir -p oracle_uploads
   docker cp doll_roulette_backend:/app/uploads/. oracle_uploads/
   ```

7. **ルートを止めておく（任意）**
   ```bash
   docker compose down
   ```

**用意するもの**: `backup_for_oracle.sql` と `oracle_uploads/` フォルダ。これらを手順 4 で VM に持っていきます。

## 手順 2: Oracle 準備（Oracle コンソール）

1. **Compute インスタンス作成**  
   コンピュート → インスタンス → インスタンスの作成。  
   - 名前: 例 `doll-roulette`  
   - イメージ: **Ubuntu 22.04**  
   - シェイプ: **VM.Standard.A1.Flex**（Always Free）が選べれば OCPU **2**・メモリ **12 GB** に。**A1 が選べない場合は VM.Standard.E2.1.Micro**（1 OCPU・1 GB）を選択し、本文の「E2.1.Micro しか Always Free にない場合」の手順に従う。  
   - パブリック IP: 割り当てる  
   - SSH キー: アップロードまたは新規生成  

2. **セキュリティリスト**  
   インスタンスのサブネット → セキュリティリスト → イングレスルールで **22（SSH）・80（HTTP）・443（HTTPS）** を追加。ソースは `0.0.0.0/0`。

3. **SSH 確認**  
   ```bash
   ssh -i 秘密鍵のパス ubuntu@パブリックIP
   ```
   ログインできたら OK。`exit` で抜ける。

**メモするもの**: パブリック IP（例: `123.45.67.89`）。ドメインは使わない場合はこの IP でアクセスします。

## 手順 3: VM セットアップ（Oracle VM に SSH した状態）

1. **Docker 導入**
   ```bash
   sudo apt update && sudo apt upgrade -y
   sudo apt install -y docker.io docker-compose-v2 git
   sudo usermod -aG docker ubuntu
   ```
   `exit` して再度 SSH し直す。

2. **アプリのコードを VM に置く**  
   - Git の場合: `git clone あなたのリポジトリURL` で `~/doll_roulette` に。  
   - 手元から転送: 手元で `rsync -avz --exclude node_modules --exclude .git --exclude pre ルートのパス/ ubuntu@パブリックIP:~/doll_roulette/`

3. **本番用 .env を作成**
   ```bash
   cd ~/doll_roulette
   cp .env.example .env
   nano .env
   ```
   以下を**必ず自分の環境に合わせて**設定（パブリック IP は手順 2 でメモした値）:
   - `POSTGRES_PASSWORD` … 強力なパスワードに変更  
   - `NODE_ENV=production`  
   - `VITE_API_BASE_URL=http://パブリックIP`（ドメインを使う場合は `https://ドメイン` に後で変更）  
   - `ALLOWED_ORIGIN=http://パブリックIP`（同上）  
   - `APP_PASSWORD=入室用パスワード`

## 手順 4: データ投入（Oracle VM）

1. **手元の PC から VM にファイルを転送**
   ```bash
   scp -i 秘密鍵 backup_for_oracle.sql ubuntu@パブリックIP:~/doll_roulette/
   scp -i 秘密鍵 -r oracle_uploads ubuntu@パブリックIP:~/doll_roulette/
   ```

2. **VM で DB だけ起動**
   ```bash
   cd ~/doll_roulette
   docker compose up -d db
   ```
   数十秒待つ。

3. **DB を空にしてからリストア**
   ```bash
   docker compose exec -T db psql -U doll_roulette doll_roulette -c "DROP TABLE IF EXISTS histories, doll_images, outing_images, outing_dolls, outings, dolls CASCADE;"
   docker compose exec -T db psql -U doll_roulette doll_roulette < backup_for_oracle.sql
   ```

4. **画像を backend から参照できる場所に置く**
   ```bash
   docker compose up -d backend
   docker cp oracle_uploads/. doll_roulette_backend:/app/uploads/
   ```

## 手順 5: アプリ・Nginx（Oracle VM）

1. **コンテナ起動**  
   - **A1 などメモリに余裕がある場合**: `docker compose up -d` で db / backend / frontend をすべて起動。  
   - **E2.1.Micro（1 GB）の場合**: 先に「E2.1.Micro しか Always Free にない場合」のとおりスワップを追加したうえで、**db と backend だけ**起動する（frontend は起動しない）。  
   ```bash
   cd ~/doll_roulette
   docker compose up -d db backend
   ```

2. **フロントを本番ビルド**  
   - **E2.1.Micro のとき**: VM ではビルドしない。**手元の PC** で `cd frontend && npm run build` し、`rsync -avz frontend/dist/ ubuntu@パブリックIP:~/doll_roulette/frontend/dist/` で VM に転送する。  
   - **A1 など VM でビルドする場合**:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt install -y nodejs
   cd ~/doll_roulette/frontend
   npm install
   export $(grep -v '^#' ../.env | xargs) && npm run build
   ```

3. **Nginx のインストールと設定**
   ```bash
   sudo apt install -y nginx
   sudo nano /etc/nginx/sites-available/doll-roulette
   ```
   以下を貼り付け、**パブリックIP** を実際の値に書き換える:
   ```nginx
   server {
       listen 80;
       server_name パブリックIP;

       location /api/ {
           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }

       location /uploads/ {
           proxy_pass http://127.0.0.1:3000;
           proxy_set_header Host $host;
       }

       location / {
           root /home/ubuntu/doll_roulette/frontend/dist;
           try_files $uri $uri/ /index.html;
       }
   }
   ```
   有効化:
   ```bash
   sudo ln -sf /etc/nginx/sites-available/doll-roulette /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```

## 手順 6: 公開後（Oracle VM）

1. **アイドル対策**
   ```bash
   crontab -e
   ```
   1 行追加: `0 8 * * * curl -s http://127.0.0.1:3000/api/health > /dev/null`

2. **動作確認**  
   ブラウザで **http://パブリックIP** を開く。パスワード入力 → かぞく一覧・ルーレット・お出かけ日記が表示されれば移設完了です。

## 任意: ベスト構成の追加（すべて無料枠内）

- **Object Storage で画像**  
  手順 5 までで画像は VM の uploads に保存されています。VM 容量を圧迫したくない場合は [OracleCloud_ベスト構成.md](./OracleCloud_ベスト構成.md) の「Object Storage を使う場合」に従い、バケット作成・Customer Secret Key・`.env` に `STORAGE_TYPE=oci` と OCI_OS_* を設定。既存画像の移行は別途スクリプトまたは新規アップロード分だけ OCI に載せる運用も可。

- **Block Volume で DB 永続化**  
  VM 再作成時も DB を残したい場合は、Block Volume をアタッチして postgres_data をそこに置く。手順は [Oracle移設_環境構築と改変手順.md](./Oracle移設_環境構築と改変手順.md) の「ブロックボリュームの追加」を参照。

- **HTTPS（ドメインがある場合）**  
  ドメインを取得し、そのドメインを VM のパブリック IP に向けたうえで:
  ```bash
  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d あなたのドメイン
  ```
  `.env` の `VITE_API_BASE_URL` と `ALLOWED_ORIGIN` を `https://あなたのドメイン` に変更し、フロントを再ビルド。

## まとめ

- **無料**: 上記すべて Always Free の範囲で実施可能。ドメイン取得は不要（IP でアクセス可）。
- **データ移行**: backup_for_oracle.sql と oracle_uploads を VM に持っていき、リストアとコピーで現状のデータをそのまま移行。
- **ベスト構成**: リファクタ済みコード＋パスワード＋Nginx。任意で Object Storage・Block Volume・HTTPS を追加可能。
- **詳細**: 各手順の細かい注意点は [Oracle移設_データ引継ぎとリファクタ移設手順.md](./Oracle移設_データ引継ぎとリファクタ移設手順.md) と [OracleCloud_ベスト構成.md](./OracleCloud_ベスト構成.md) を参照。
